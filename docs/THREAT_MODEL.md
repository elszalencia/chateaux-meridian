# Threat model

Who could take money or corrupt a plan, how, what stops them today, and which test proves it. "Open" means no mitigation is built yet. Contract test names are `cargo test` paths in `contracts/payment_plan/src/` (`test.rs`, `test_adverse.rs`, `test_frozen.rs`); services and web test names are `describe › it` in the named file.

## Assets and trust boundaries

- **USDC in the vault.** The `payment_plan` contract holds each plan's balance. It can leave only to `payee_backend` (a release) or to the plan's buyer (a refund or the leftover on completion).
- **Locked rates.** A lock fixes the COP/USD rate for one or three installments; a wrong rate is a direct loss for the buyer or for treasury.
- **Roles.** `admin` (upgrade, migrate, pause, cancel), `operator` (create plans, apply locks with the buyer, releases, adverse-event actions), the buyer (deposits, co-signs locks). The asset issuer (Circle) can freeze trustlines.
- **Off-chain inputs.** ACH status from the US on-ramp, SEP-31 payout status from the Colombian anchor, hedge settlements, and contract events read through RPC.

## Threats

| # | Threat | Attack | Mitigation | Test | Status |
| --- | --- | --- | --- | --- | --- |
| T1 | Auth replay | Re-submit a signed authorization (e.g. the buyer's `apply_lock` or `deposit` auth) to repeat it | Soroban authorization entries carry a nonce and a signature expiration ledger; the host consumes the nonce, so a signed entry cannot be used twice. Lock ids are unique per lock and `apply_lock` accepts only `Open` installments, so a replayed lock call fails on state as well | `apply_lock_needs_both_operator_and_buyer`; `apply_lock_rejects_any_installment_that_is_not_open` | Mitigated (protocol); no dedicated replay test in the repo |
| T2 | Unauthorized release | Anyone other than the operator releases funds, or a release is sent somewhere other than the payee | `release_due` and `release_spot` require the operator; the destination is the configured `payee_backend`, never an argument. Refunds can only reach the plan's buyer; `cancel_plan` is admin only. Every adverse function rejects a non-operator | `release_due_waits_for_the_due_date_pays_the_payee_once_and_only_for_the_operator`; `cancel_plan_is_admin_only_and_the_refund_can_only_reach_the_buyer`; `every_adverse_call_is_rejected_for_a_non_operator` | Mitigated |
| T3 | Operator key compromise | Attacker with the operator key releases early, breaks locks or marks plans missed | Releases still go only to `payee_backend`; refunds only to buyers; `release_due` waits for the due date. The admin can `pause` deposits, locks, releases and refunds while the key is rotated | `pause_is_admin_only_and_blocks_deposits_locks_releases_and_refunds` | Partly mitigated. Operator key rotation without a redeploy and a multisig operator are **open** |
| T4 | Admin key compromise | Attacker upgrades the contract to new code and drains the vault | `upgrade` and `migrate` are admin only. Nothing else stops a malicious upgrade | `upgrade_and_migrate_are_admin_only_and_migrate_is_idempotent` | **Open**: admin as a multisig (or timelocked upgrade) is not built |
| T5 | Double or replayed deposit | The same ACH payment is deposited twice, or a deposit is credited to two installments | `deposit` needs the buyer's auth and only adds to the plan balance; an installment is released once (status `Released`), and `release_*` fails with `InsufficientBalance` rather than overdrawing. Idempotency of the on-ramp → deposit step (one deposit per on-ramp transaction id) belongs to the anchor integration | `deposit_requires_the_buyer_and_moves_usdc_into_the_plan`; `release_fails_with_insufficient_balance_and_keeps_state`; `release_due_…_pays_the_payee_once_…` | On chain mitigated; off-chain idempotency key **open** until the anchor integration lands |
| T6 | ACH reversal | Buyer's bank returns the ACH debit after USDC was credited (fraud or NSF) | The plan can be put `OnHold` with reason 303 (`ACH_RETURN`), which blocks further deposits, locks and releases. Who carries a loss already released is a policy decision (ADVERSE_EVENTS.md D9) | `place_hold_blocks_funds_and_lift_hold_restores_the_previous_state`; `transitions.test.ts › plan-level transitions › place_hold remembers the state and lift_hold restores it; blocked plans refuse marking` | Mechanism built; the trigger from the on-ramp status and the loss policy are **open** |
| T7 | Forged anchor callbacks | Attacker posts a fake "completed" SEP-24 or SEP-31 status to the backend | The backend must treat a callback only as a hint and confirm by querying the anchor's `GET /transaction` with its own SEP-10 token; the contract never trusts a callback (releases are operator calls on chain state) | — | **Open**: verification lives in the anchor integration, not built on this branch |
| T8 | Rate tampering from the browser | The client submits a better locked rate than quoted | The rate is computed by the lock engine (`services/src/lock/engine.ts`) and stored with the quote; `acceptLock` takes only the quote id, refuses an expired or already-used quote and sends the stored rate, in fixed point, to `apply_lock`. In testnet mode the whole service layer runs in the Node server (`services/server/`): the browser calls `POST /api/acceptLock` with the quote id only and never builds or signs a transaction. In mock mode the service layer runs in the browser, which is acceptable only because nothing is real | `DemoApi.test.ts › an expired quote cannot be accepted and is marked vencido`; `bridge.test.ts › acceptLock on María Q3 calls apply_lock with locked_rate 34444266667n, idxs 6..8 and a one-minute expiry`; `demo-script.testnet.spec.ts` (step 2 through the server) | Mitigated |
| T9 | Secret exposure in the front end | Signing keys shipped to the browser | Every testnet secret lives in the gitignored `.env.testnet` and is read only by the Node server and the scripts (`services/server/src/config.ts`); the only `VITE_`-prefixed value is `VITE_DEMO_MODE`, and the server refuses to start on the old `VITE_*_SECRET` names. `npm run check:bundle` builds the web app in testnet mode and fails if the output holds a secret seed (`S[A-Z2-7]{55}`), any secret value from `.env.testnet` or a secret variable name. Tracked files are scanned for secret keys before every commit | `npm run check:bundle` (6 files, 15 secret values checked: pass); secret-key scan of tracked files | Mitigated. Testnet keys only; never reuse them |
| T10 | Issuer freeze | Circle revokes authorization of the vault, the payee or the buyer (USDC is `auth_revocable`; clawback is not enabled, so balances cannot be taken) | Transfers that hit a freeze return `AssetFrozen` and write nothing; `hold_frozen` (permissionless, verified on chain) moves the plan `OnHold` with reason 304; `lift_hold` refuses until reauthorized; the daily job checks every plan | `test_frozen.rs`: `a_frozen_vault_makes_releases_fail_with_asset_frozen_and_writes_nothing`, `a_frozen_payee_or_buyer_is_also_a_freeze`, `hold_frozen_needs_no_auth_records_reason_304_and_blocks_lift_until_reauthorized`, `a_cancelled_plan_with_a_frozen_vault_keeps_its_balance_until_the_refund_can_land`, `a_transfer_failure_without_a_freeze_stays_transfer_failed`; `adverseEvents.test.ts › runAdverseEventsDaily › a frozen plan is put on hold (reason 304) instead of being worked on` | Mitigated (no stuck plan). Recovering frozen funds is a legal matter, out of scope |
| T11 | TTL lapse | A dormant plan's entries are archived and the plan becomes unreadable (or must be restored) | `extend_ttl` is permissionless and extends the instance, the plan, its governance and every installment; a keeper job calls it on a schedule | `extend_ttl_keeps_the_plan_readable_past_the_default_ttl`; `without_extension_the_ttl_runs_down_to_the_archive_point` | Contract side mitigated; the keeper job's schedule is part of the job registry on the rails branch |
| T12 | RPC event gap | The indexer misses events (RPC retention window, downtime) and the off-chain store diverges from the chain | `get_status`, `get_installment` and `get_governance` let any reader rebuild a plan from chain state; every adverse action writes its evidence hash both on chain (event) and off chain (`policy_events`) so the two can be matched | — | **Open**: cursor persistence and a periodic reconcile from `get_status` belong to the indexer on the rails branch |
| T13 | Paused contract abused | The admin pauses to block a buyer's refund | Pause is a single admin flag, visible on chain (`PauseChanged` event, `is_paused`), and the same admin key could upgrade anyway; covered by T4 | `pause_is_admin_only_and_blocks_deposits_locks_releases_and_refunds` | Accepted risk while the admin is a single key |
